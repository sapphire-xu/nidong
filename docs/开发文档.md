# 泥洞 · 开发文档

桌面小看板的技术说明、开发计划和**已实测**的东大数据抓取方式。视觉见 [视觉设计.md](视觉设计.md)。

探测日期：2026-09-07（校外）、**2026-09-08（校园网）**。账号形态：本科生学号 + 统一身份认证。学校随时改接口，本文件把「已跑通」和「未跑通」分开写。校园网下本次密码登录**未触发二次认证**。

---

## 1. 目标与非目标

**做**

- Windows 与 macOS 同一套界面：顶栏悬停岛，展开看校园卡、网费、电费、今日课表；点校园卡看**本月**花费柱 + 当日流水，可翻历史月；点「学期」看本学期周历
- 用户在本机登录一号通；新设备走学校二次认证（图形码本机 OCR 预填 + 短信手输）
- 会话、密码只放本机（系统钥匙串）
- 余额定时刷新；课表按**学期整表缓存**，不每天打教务

**不做（v1）**

- 充值、缴费下单、挂失、选课
- 把别人的账号收到自己服务器
- 公开网站版查询
- 破解验证码服务端、绕过二次认证（本机 OCR 只帮用户读自己的图形码，短信仍要本人填）
- 自定义任务 / 日程（v1.x）

v1 的成功标准：登录一次后，展开岛能看到真实卡余额、网费余额与用量、（若已填房间码）电费余量、从学期缓存推出来的今日课程；点开校园卡能看到与 ecard 网页对得上的**本月**花费柱，并能翻到已缓存的上个月。校园网直连一卡通/教务；校外先 WebVPN 再拉同一套数据。登录同步和手动刷新都走 `refresh_inner`，不要先报「校外连不上」再靠手动刷新才成功。

## 2. 关键决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 壳 | **Tauri 2 + Rust + React + TypeScript** | Win/Mac 一套 Web UI；体积远小于 Electron；透明置顶窗、托盘、自启都有现成能力 |
| 抓数 | Rust 侧 `reqwest` + cookie jar，UI 不直接打学校 | 会话、RSA、重试集中在一处；以后接口改了只动 core |
| 密码 | OS keyring（Windows Credential Manager / macOS Keychain） | 不要写明文配置文件 |
| 验证码 | 本机 OCR 预填学校图形码；失败手输；短信用户手输 | 东大图形码极简；图不离开本机；不接打码平台 |
| 课表 | **`jwxt.neu.edu.cn` JSON 整学期拉一次**，本地缓存；今日/周历都从缓存推 | 校园网 2026-09-08 已跑通；选课后课表固定。旧 EAMS 仅备选 |
| 多用户 | 本机可换账号，但同一时间一个会话 | 产品是私人看板，不是门户 |

备选壳：Electron（团更熟、包更大）、纯 WPF+Swift（两套 UI，不采用）。

## 4. 窗口与系统

一个主 WebView，两套几何（登录/验证/设置都是岛内叠层，不要再开系统窗）：

1. **收起** 无边框透明窗，始终置顶，高 40px，水平居中**贴顶（y = 0）**。
2. **展开** 同一窗口加高，上限 560。

交互、钉住、自动隐藏、上课提醒、托盘以**当前代码**为准，见 [给AI.md](给AI.md)「窗口状态」。早期稿里的距顶 8px、托盘只有刷新/退出，已经改过。

位置：只拖，设置里不要放位置项。拖丢了：托盘「复位岛」，或双击收起态 Logo。

Win 与 Mac 的毛玻璃用各自 API，UI 只提供 token，不在 CSS 里写死不透明白底。

## 5. 数据模型（UI 只认这个）

```ts
type Snapshot = {
  fetchedAt: string;          // ISO
  network: "campus" | "offcampus" | "unknown";
  card?: { balance: number; subsidy: number; status: string };
  cardBills?: Bill[];         // 正在看的那个月的原始流水
  cardSpend?: DaySpend[];     // 该月 1…月末，含 spend=0 的空桶；UI 只读这个
  cardMonth?: string;         // "YYYY-MM"
  net?: { balance: number; monthBytes: number; monthSeconds: number; monthTimes: number };
  elec?: { remainKwh: number; roomNo: string; lastReadAt?: string } | { unbound: true };
  coursesToday?: Course[];    // 从 semester 推导，不是另一份真源
  semester?: SemesterTable;
  errors: Partial<Record<"card"|"net"|"elec"|"course"|"auth", string>>;
};

type Course = {
  name: string;
  place: string;
  teacher?: string;
  start: string;  // "08:00"
  end: string;    // "09:35"
  weekday: 1|2|3|4|5|6|7;
  weeks?: number[];            // 开课周；缺省 = 全学期
  sections?: [number, number]; // 节次闭区间，如 [1,2]
};

type SemesterTable = {
  semesterId: string;
  label: string;               // "2026-2027 秋季"
  week1Monday: string;         // YYYY-MM-DD
  fetchedAt: string;           // ISO，课表上次成功拉取
  courses: Course[];
};

type Bill = {
  time: string;       // ISO，来自「操作时间」
  subject: string;    // 科目描述，如 食堂消费 / 银行转账
  amount: number;     // 钱包交易金额：负=消费，正=充值
  fee?: number;       // 管理费
  balanceAfter: number;
  station?: string;   // 工作站或终端名称
};

type DaySpend = {
  date: string;       // YYYY-MM-DD，本地日历日
  spend: number;      // 当日消费合计 = sum(-amount where amount < 0)
  recharge: number;   // 当日充值合计 = sum(amount where amount > 0)，不进柱高
  count: number;      // 消费笔数（amount < 0）
  bills: Bill[];      // 当天全部流水，时间倒序
};
```

日花费柱用 `cardSpend`，不要让 UI 自己扫 `cardBills` 再聚合一遍。缺的日子（含本月还没到的日子）要补 `spend: 0` 的空桶，柱数 = 当月天数。

账单按月落盘：`bills-2026-09.json` 这种。历史月原则上不再变，命中缓存就直接画；本月跟卡一起刷新。今日课表 = `semester.courses` ∩ 当前教学周 ∩ 星期 ∩ 节次。

刷新策略：

| 数据 | 间隔 | 失败 |
|---|---|---|
| 卡、网、电 | 20 分钟 | 显示缓存 + 卡片内错误 |
| 账单 · 本月 | 跟卡同一次 ecard 会话 | 柱可晚于余额出现 |
| 账单 · 历史月 | 用户翻到该月且本地没有才拉；拉完缓存 | 保留空月 + 重试 |
| 课表 · 学期整表 | **不按天拉。** 无缓存 / 用户点「重新同步」 / 学期 id 变了才打 EAMS | 有缓存就继续用；无缓存且校外失败 → 7.8 |
| 登录会话 | 请求 401/跳到登录页时静默重登；要短信则提示用户 |

不要并发打爆教务。一次定时刷新内卡/网/电可并行，课表不参与定时刷新。

## 6. 认证（统一身份认证）

### 6.1 入口

- 直连：`https://pass.neu.edu.cn/tpass/login?service=<业务 service>`
- 校外：`ecard` / `jwxt` 等校园网主机不能直连。登录和刷新前 `probe_campus_net`（探测 `ecard:80`、`jwxt:443`，约 30 秒缓存），不通则 `ensure_webvpn`（一号通换 WebVPN 票，失败再试一次），再把内网 URL 编成 `https://webvpn.neu.edu.cn/...`。能打开 `pass.neu.edu.cn` 不等于能打开一卡通。校园网探测成功则 `webvpn_on=false`，不要走加密 URL。
- 不要把 WebVPN 换票和校园卡请求塞进同一个 22 秒超时里。账单等卡的 SSO 回来再拉。

常用 service：

| 业务 | service |
|---|---|
| 信息门户 | `https://portal.neu.edu.cn/tp_up/` |
| 校园卡 | `http://ecard.neu.edu.cn/selflogin/login.aspx` |
| 缴费大厅 | `https://pay.neu.edu.cn/drCasLogin`（实测会进 `/openPortal`） |

| 旧 EAMS（备选） | `http://219.216.96.4/eams/homeExt.action` |

### 6.3 二次认证（新设备，已摸清未在本次会话走完短信）

页面文案：「为保障您的账号安全，当前设备需进行身份验证」。脚本：`/tpass/comm/neu/js/login_second.js`。

发短信：

1. 图形码 `GET https://pass.neu.edu.cn/tpass/code?_=<ts>`（与登录同一 `JSESSIONID`）
2. `POST https://pass.neu.edu.cn/tpass/secondAuthCode`  
   `code=<图形码>&method=mobile`  
   相对路径相对 `/tpass/login` 解析为 `/tpass/secondAuthCode`
3. 成功后再提交短信

提交二次认证：

- 表单仍 `POST /tpass/login?service=...`
- `execution`、`RelayState` 为 `e1s2`
- `_eventId=submit`
- 短信输入框 id：`scendAuthCode`（学校拼写就是 scend）
- 可勾选信任设备

也可邮箱、企业微信扫码。v1 只做短信。

### 6.3.1 图形码 OCR（本机）

东大 `/tpass/code` 的图是短英数，干扰弱，适合离线识别。**图和识别结果都不上传。** 不是打码平台，也不是绕过二次认证：短信仍要本人填。

**首选：** 把 [ddddocr](https://github.com/sml2h3/ddddocr) 的 `common_old.onnx`（约 13MB）嵌进 Rust，用 `ort` 或现成 crate（[ddddocr-rs](https://github.com/mzdk100/ddddocr-rs) / [86maid/ddddocr](https://github.com/86maid/ddddocr)）推理。进程内调用，启动时加载一次模型，不要每次弹验证层都重新 init。

**约束字符集：** 先对真实图抽样。若只有 `0-9A-Za-z`，调用时把 charset 收窄，少认成汉字。

**备选：** 若 13MB 嫌大或误识高，用 `dddd_trainer` 对着东大图形码风格合成数据训一个 4 位 CNN（目标 <1MB）。Tesseract 不当主路径（验证码上准确率差）。

**失败：** 输入框留空、焦点进去、图仍显示。用户改完再点发送。OCR 不得自动点「发送」。

**产品流程：** 密码正确但返回二次认证页 → 岛内打开验证层 → 本机 OCR 预填图形码（用户可改）→ 点发送 → 填 6 位短信 → 继续用同一个 cookie jar 换 ST。

同一台电脑、短期内再次登录可能不再要短信（本次探测第二次就直接出 ST）。程序不能假设永远跳过。

### 6.4 换票

`GET https://pass.neu.edu.cn/tpass/login?service=<url>`（已有 `CASTGC`）→ `302 Location: <url>?ticket=ST-...`  
ST **一次性**。换校园卡和换缴费大厅要两次。

## 7. 各业务怎么抓（只写实测）

以下 URL、字段、返回都在 2026-09-07 用真实会话打通过。HTML 选择器会变，优先 JSON。

### 7.1 校园卡余额 —— 可用

**路径 A（推荐）一卡通自助查询**

1. CAS service = `http://ecard.neu.edu.cn/selflogin/login.aspx`
2. 跟随后得到自动提交表：

```
POST http://ecard.neu.edu.cn/selfsearch/SSOLogin.aspx
username, timestamp, auid
```

3. 进入 `Index.aspx` / `User/baseinfo.aspx`

余额在：

- `#ContentPlaceHolder1_txtOddFare` 主钱包，如 `399.07 元`
- 补助：页面文案「补助余额」
- `#ContentPlaceHolder1_txtSpecialOddFare` 专用钱包
- `#ContentPlaceHolder1_txtStatus` 卡状态

`https://ecard.neu.edu.cn` TLS 证书过期，校园网内**用 http**。校外不要直连这台机，走 WebVPN。

**路径 B 门户小组件**

`POST https://portal.neu.edu.cn/tp_up/up/subgroup/getCardMoney`  
`Content-Type: application/json`，body `{}`  
本次探测**两次读超时**（20s / 60s）。不要当主路径；可作校园网内备选。

### 7.2 校园卡账单 —— 可用

`http://ecard.neu.edu.cn/selfsearch/User/ConsumeInfo.aspx`

ASP.NET 表单：先 GET 拿 `__VIEWSTATE`、`__EVENTVALIDATION`，再 POST：

| 字段 | 值 |
|---|---|
| `ctl00$ContentPlaceHolder1$rbtnType` | `0` 主钱包 |
| `ctl00$ContentPlaceHolder1$txtStartDate` | `YYYY-MM-DD` |
| `ctl00$ContentPlaceHolder1$txtEndDate` | `YYYY-MM-DD` |
| `ctl00$ContentPlaceHolder1$btnSearch` | `查  询`（首页） |
| 翻页 | `__EVENTTARGET=ctl00$ContentPlaceHolder1$AspNetPager1`，`__EVENTARGUMENT=页码` |

表格列：操作时间、科目描述、钱包交易金额、管理费、钱包余额、操作员、工作站、终端名称。

v1 **要做**自然月日花费柱（视觉 §8.1）：点校园卡进入，默认 **当前自然月**，可往前翻月。生活费按月给，不要滚动 30 日。

拉取：

- 打开账单或定时刷新：拉 `cardMonth`（默认本月）`txtStartDate=月初`、`txtEndDate=月末`（本月则 end=今天，不必把未来日期丢给学校）。
- 用户翻到尚未缓存的历史月：当场拉那一个月，写入 `bills-YYYY-MM.json`。
- 每页约十几笔，食堂月常过百笔。**单月最多 10 页**，禁止狂翻、禁止一次拉全年。
- 默认可往前翻 12 个自然月；再早的月点到再拉，拉失败就停。
- 本月缓存 TTL 跟卡一样 20 分钟；历史月默认不再自动刷新（流水不会回头改）。用户在该月点刷新则重拉。

聚合（在 `fetch/card.rs`，不要丢给 UI）：

1. 解析金额：去掉「元」、逗号；消费为负、充值为正。若网页把消费写成正数+「支出」文案，以列含义为准，写入 `Bill.amount` 时统一成「带符号」。
2. 按 **本地自然日** 分桶（不要用 UTC 切日，食堂 23:50 的餐应算当天）。
3. `DaySpend.spend` 只加 `amount < 0` 的绝对值。充值不进柱高；管理费若单独成行且为负，算消费。
4. 输出该月每一天的桶（28–31 个），没流水的也是 `spend: 0`。本月里今天之后的日子同样空桶，UI 标「还没到」。
5. 翻满 10 页仍有下一页：`errors.card = "bills_truncated"`，UI 底栏「本月可能不完整」。

科目不在图上分色。

### 7.3 网费余额与用量 —— 可用

**用量（门户 JSON，推荐）**

```
POST https://portal.neu.edu.cn/tp_up/up/subgroup/getWlzzList
Content-Type: application/json;charset=UTF-8
Origin: https://portal.neu.edu.cn
Referer: https://portal.neu.edu.cn/tp_up/view?m=up
body: {}
```

实测：

```json
{
  "user_balance": 0,
  "sum_seconds": "232251",
  "user_charge": "0",
  "sum_times": "20",
  "sum_bytes": "2038540630"
}
```

| 字段 | 含义 |
|---|---|
| `user_balance` | 余额，元 |
| `sum_bytes` | 本月已用流量，字节。v1 **要显示**在网费卡上 |
| `sum_seconds` | 本月时长，秒（v1 卡面不展示，可留 tooltip） |
| `sum_times` | 连接次数（v1 卡面不展示） |
| `user_charge` | 本月消费（待再确认，卡面不用） |

网费卡：主数字仍是余额（元）；次行「已用 1.90 GB」。`sum_bytes` 格式化：`≥ 1 GiB` 用 GB 一位小数，否则 MB 整数。探测样例 `2038540630` → **1.90 GB**。余额 0 也要画流量，不要只剩「见底了」。

余额走缴费大厅，流量走门户。门户 JSON 偶发解析不到时**不要把流量写成 0B**（会看起来像没用过网）；沿用上次成功值，从未成功过则显示「已用 —」。只有 `sum_bytes` 明确出现才显示 0B。

需先用门户的 service 换票，让 `portal.neu.edu.cn` 种会话（本次还出现 `personal.neu.edu.cn` 与 `SESS_ID`）。

**余额（缴费大厅，推荐与门户对拍）**

1. CAS：`https://pay.neu.edu.cn/drCasLogin` → `/openPortal`
2. `POST https://pay.neu.edu.cn/queryNetAccBalance`  
   `netNo=<学号>&netType=1&factorycode=N005`  
   `netType` 空会「参数异常」，`0/1/2/4/5` 均可，v1 用 `1`
3. 返回 `{"returncode":"SUCCESS","netaccbal":"0"}`
4. 补充：`POST https://pay.neu.edu.cn/getNetAccBalanceAccount` `netNo=<学号>`  
   `JSONdata.balance`、`user_real_name`、`products_id`

项目列表（调试用）：`POST https://pay.neu.edu.cn/queryProList`  
网费项：`id=247`，`payproname=网费`，`interurl=netdetails`，`factorycode=N005`。

### 7.4 电费余量 —— 已跑通


成功后种 `_WEU`，跳到 `/jwapp/sys/homeapp/home/index.html?av=&contextPath=/jwapp`。

请求头：

```
Fetch-Api: true
Referer: https://jwxt.neu.edu.cn/jwapp/sys/homeapp/home/index.html?av=&contextPath=/jwapp
```

前缀 `https://jwxt.neu.edu.cn/jwapp/sys/homeapp`

| 接口 | 参数 | 用途 |
|---|---|---|
| `GET /api/home/student/schoolCalendars.do` | 无 | 当前学期 `itemCode`，实测 `2026-2027-1` |
| `GET /api/home/student/getMyScheduleDetail.do` | `termCode` | **格子课表，看板主数据** |
| `GET /api/home/student/courses.do` | `termCode` | 课程清单 + 地点文本 |
| `GET /api/home/student/getMyScheduledCampus.do` | `termCode` | 校区，实测浑南 `01` |
| `GET /api/home/student/getSections.do` | `termCode` | 节次名；钟点以课表条目为准 |
| `GET /api/home/student/exams.do` | `termCode` | 考试，可空 |

**`getMyScheduleDetail` 实测：** `arrangedList` 21 条，`notArrangeList` 含军训等未排教室课。条目含 `courseName`、`placeName`、`campusName`、`dayOfWeek`（1=周一）、`beginSection`/`endSection`、`beginTime`/`endTime`、`weeksAndTeachers`。

v1 只用 `arrangedList`，解析周次后筛「本周 ∩ 今天」。整学期 JSON 缓存为 `semester.json`，之后今日/周历都读缓存，定时刷新**不打课表**。

**2026-09-08 校园网：** 无二次认证，一次拉全。  
**2026-09-07 校外：** 旧 EAMS 循环跳转，不要当主路径。校外 `jwxt` 走 WebVPN 打同一套 JSON；仍不通时有缓存就显示，无缓存才失败条。

旧 EAMS `219.216.96.4` **降为备选**。

钟点：**优先用每条课的 `beginTime`/`endTime`。** 缺字段时，用该课的校区去查官方作息（§7.5.1）。不要让用户在设置里手选南湖/浑南。

校区判定（自动，按课）：

1. 条目 `campusName` 含「浑南」→ 浑南；含「南湖」→ 南湖
2. 否则 `getMyScheduledCampus.do`（实测浑南 `01`）
3. 再否则看 `placeName`：大成 / 何世礼 / 逸夫 / 机电 / 采矿 / 冶金 → 南湖；文管 / 生命 / 文科 / 信息科学 → 浑南
4. 仍未知：跟本学期 `arrangedList` 里出现次数最多的校区

跨校区课表合法：同一周可以上午浑南、下午南湖。周历左列钟点用**本周多数校区**；格子 tooltip 永远用**这门课自己的**校区/JSON 钟点。

### 7.5.1 官方作息（用户提供的《东北大学教学作息时间表》）

南湖、浑南 **上午不同**（浑南各节晚 30 分钟），**下午和晚上相同**。共 12 小节。周历按两节连排合成 6 个大节格。

| 小节 | 南湖 | 浑南 | 周历格 |
|---|---|---|---|
| 1 | 08:00–08:45 | 08:30–09:15 | **1–2** 南湖 08:00–09:40 / 浑南 08:30–10:10 |
| 2 | 08:55–09:40 | 09:25–10:10 | |
| 3 | 10:00–10:45 | 10:30–11:15 | **3–4** 南湖 10:00–11:40 / 浑南 10:30–12:10 |
| 4 | 10:55–11:40 | 11:25–12:10 | |
| 5 | 14:00–14:45 | 14:00–14:45 | **5–6** 14:00–15:40 |

落盘：`config/periods.json` 内含 `nanhu` / `hunnan` 两套。**设置里不要校区开关。**

教学周：用学期第一周周一（设置或官方校历）+ 今天日期计算。v1 可手动填「本学期第一周周一」。

**何时重新拉课表**

| 触发 | 行为 |
|---|---|
| 本学期 `semester.json` 不存在 | 校园网下自动拉一次 |
| 用户点课表旁「重新同步」 | 强制打 jwxt，成功才覆盖缓存 |
| EAMS 返回的 `semester.id` 与缓存不同 | 视为新学期，重新拉 |
| 每天打开 / 20 分钟余额刷新 | **不拉课表** |

节假日调休、临时停课：教务课表往往不改。v1 不自动吃通知；用户仍按缓存显示。v1.x 自定义日程用来盖某一天（实验、班会、放假）。

缓存里要留下 `weeks` / 单双周，周历翻到第 n 周才能滤对。

## 8. 抓数时序

```
启动
  → 钥匙串读账号
  → cookie 未过期？直接 Snapshot
  → 否则 CAS 密码登录
       → 若二次认证：UI 要图形码+短信，恢复
  → prepare_access（校园网直连 / 校外 WebVPN）
  → 并行：
       A 门户 ST → getWlzzList
       B 一卡通 ST → SSOLogin → baseinfo
       C 缴费 ST → queryNetAccBalance（与 A 对拍）
       D 若有房间码 → queryRommInfo
       E 学期缓存缺失或学期变了 → jwxt getMyScheduleDetail（校外经 WebVPN）
  → 账单：卡 SSO 回来后再拉本月（若缓存过期）
  → 写入本地缓存 snapshot.json（无密码）+ semester.json
```

换 ST 必须串行拿票、并行拉业务，避免一个 ST 用两次。

## 9. 安全

- 密码、短信只在内存和 OS keyring。cookie jar 文件权限仅用户可读。
- 不写进 git、日志、崩溃报告。日志里学号可留，密码/ST/CASTGC 打码。
- TLS：门户、pass、pay 走系统根证书。ecard 用 http 是对方证书过期，不在客户端关全局 verify。
- 刷新下限 5 分钟。
- 关于页写清：非官方、数据来自用户自己的一号通。

## 11. 测试

| 项 | 方法 |
|---|---|
| RSA 登录 | 错密码应停在登录页；对密码得 TGT 或二次认证 |
| 二次认证 | 错图形码、错短信、超时 |
| 图形码 OCR | 用真实 `/tpass/code` 图抽样；对的要预填，错的必须能手改；断网仍能识别（模型在本地） |
| 卡 | 与 ecard 网页数字一致 |
| 账单柱 | 抽本月 3 天手工加总，与柱高/tooltip 一致；充值日柱高不含充值；未来日「还没到」；翻月柱数 = 当月天数 |
| 网 | 门户 JSON 与缴费大厅 `netaccbal` 一致；卡面已用流量与 `sum_bytes` 换算一致 |
| 电 | 用用户自己的房间码；错误码不得误显示别人的电 |
| 课表 | 与 `jwxt`「我的课表」对比；浑南上午 08:30 起、南湖 08:00 起；跨校区课各用各的钟点；杀进程再用缓存 |
| 会话过期 | 清 cookie 后应回到登录而不是空转 |
| 校外 | 登录后卡/网/电/课都能拉（WebVPN）；超时写「请再刷新一次」，不要写「校外连不上」 |

用用户自己的号测。仓库里放 mock snapshot，CI 不打学校。
